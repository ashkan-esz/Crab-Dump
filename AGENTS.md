# Repository Guidelines

## Project Structure & Module Organization

This is a single-binary Rust project (`pg-backup-tg`) with a flat `src/` layout — no crates or submodules:

| Path | Purpose |
|---|---|
| `src/main.rs` | CLI entry point, pipeline orchestration |
| `src/config.rs` | Env-var loading & validation via `clap`/`anyhow` |
| `src/dump.rs` | Spawns `pg_dump`, reads stdout |
| `src/compress.rs` | Wraps a writer in a `zstd` encoder |
| `src/encrypt.rs` | Wraps a writer in an `age` (X25519) encryptor |
| `src/chunk.rs` | Rolling `ChunkWriter` — splits streams into ≤49 MiB `.partNN` files |
| `src/telegram.rs` | Sends documents to Telegram Bot API (with retries) |

Other roots: `Cargo.toml` (dependencies), `Dockerfile` (multi-stage build), `docker-compose.yml`, `.env.example` (config template).

## Build, Test, and Development Commands

| Command | What it does |
|---|---|
| `cargo build --release` | Compile the binary to `target/release/pg-backup-tg` |
| `cargo test` | Run unit tests (chunk rolling / reassembly) |
| `cargo run --release -- --dry-run` | Validate config + `pg_dump` availability without running a backup |

## Coding Style & Naming Conventions

- **Edition:** Rust 2021
- **Formatting:** `rustfmt` (standard — run `cargo fmt` before submitting).
- **Linting:** `clippy` — run `cargo clippy -- -D warnings`.
- **Naming:** modules are `snake_case`; types and enums are `PascalCase`; functions and variables are `snake_case`; private items are kept module-scoped via `mod` visibility.
- **Error handling:** `anyhow::Result` for the public API, `thiserror` for library-level error types. Always `.context("message")` on fallible calls.
- **Logging:** `tracing` with `tracing-subscriber::EnvFilter` — configure via `RUST_LOG`.

## Testing Guidelines

Tests live alongside their modules (e.g., `src/chunk.rs` contains tests at the bottom of the file). Run with `cargo test`. The project currently covers unit-level logic — the streaming pipeline and Telegram upload are integration-grade and exercised end-to-end manually.

## Commit & Pull Request Guidelines

Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/):

- `feat:` — new functionality (e.g. `feat: make the encryption optional`)
- `chore:` — maintenance (e.g. `chore: save the code generated by zcode glm2`)
- `fix:`, `refactor:`, `docs:`, `test:` — also used as appropriate

For pull requests, include a brief description, link any related issues, and note any config or env-var changes.

## Configuration Tips

All settings come from environment variables (load via `set -a; source .env`). Required vars: `DATABASE_URL`, `TG_BOT_TOKEN`, `TG_CHAT_ID`. Optional: `AGE_RECIPIENT` (encryption public key), `SOCKS_PROXY`, `CHUNK_SIZE_MB`, `WORK_DIR`, `RUST_LOG`. See `src/config.rs` for defaults.
